# 🤖 Инструкции для ИИ Агентов (AI Agent Protocol & Guidelines)

> **ВАЖНО:** Данный репозиторий разрабатывается и поддерживается **распределенной сетью ИИ-агентов** и людей-инженеров, работающих **параллельно** с **разных физических/виртуальных машин** и под управлением **разных моделей ИИ** (Claude, GPT, Gemini, Qwen и др.).

Все агенты **ОБЯЗАНЫ** строго следовать протоколу, описанному в данном документе.

---

## 1. 🌐 Архитектура параллельной распределенной работы

1. **Многомашинность и независимость**:
   - Каждый агент может работать в изолированном окружении (Docker, виртуальная машина, локальный сервер, Sandbox).
   - Нельзя рассчитывать на общее локальное дисковое пространство между машинами — синхронизация происходит **исключительно через Git-репозиторий**.

2. **Параллелизм без конфликтов**:
   - Перед началом любой задачи агент обязан синхронизировать ветку (`git pull --rebase`).
   - Перед взятием задачи в работу агент проверяет `STATUS.md` и `agent_state.json`.
   - Если задача уже помечена статусом `IN_PROGRESS` другим агентом, переключайтесь на свободную задачу или создавайте подзадачу/новую функциональность в отдельной ветке.

---

## 2. 📍 Фиксация статуса работы и текущего шага (`STATUS.md`)

Каждый агент обязан непрерывно транслировать свой прогресс, чтобы другие агенты видели, кто над чем работает:

1. **Перед началом работы над задачей**:
   - Обновить файл `agent_state.json` и `STATUS.md`, указав:
     * `agent_id`: уникальный идентификатор агента (например, `Agent-Europe-01`, `Agent-Claude-3.7-Worker`).
     * `machine_id` / `host`: хост или IP/ID среды.
     * `task_name`: название выполняемой задачи.
     * `current_step`: текущий выполняемый шаг (например, *"Глубокий поиск BGP префиксов провайдеров Франции"*).
     * `status`: `IN_PROGRESS`.
     * `timestamp`: текущее время (ISO 8601).
   - Закоммитить и запушить обновление статуса: `git commit -am "chore(status): Agent-01 started step [X]" && git push`.

2. **В процессе выполнения**:
   - При переходе к новому шагу обновлять поле `current_step` в `STATUS.md`.

3. **По завершении шага/задачи**:
   - Перевести статус в `COMPLETED` в `STATUS.md`.
   - Зафиксировать результат и метрики в блоке *Changelog & Milestones*.

Для автоматизации используйте скрипт:
```bash
# Взять задачу:
python3 agent_sync.py lock --agent "Agent-01" --task "Data Enrichment" --step "Downloading RIPE datasets"

# Обновить текущий шаг:
python3 agent_sync.py step --agent "Agent-01" --step "Indexing 50,000 subnets into SQLite"

# Завершить задачу:
python3 agent_sync.py complete --agent "Agent-01" --task "Data Enrichment"
```

## 3. 🧠 Превращение лога работы в основной скилл (Skill Generation)

**Правило:** *Весь лог успешной работы агента, преодоления ошибок и решения задач должен немедленно превращаться в переиспользуемый СКИЛЛ (Skill)*.

1. Любая завершенная задача или новая возможность документируется в папке `skills/` в формате Markdown: `skills/<skill_slug>.md`.
2. **Структура файла скилла:**
   - `Название скилла` и `Контекст применения`.
   - `Входные данные и предварительные требования`.
   - `Пошаговый алгоритм выполнения`.
   - `Готовый проверенный код / CLI команды`.
   - `Типичные ошибки, граничные случаи и как их обходить`.
   - `Критерии верификации результата`.
3. Скилл должен быть самодостаточным: любой другой агент на любой другой машине должен мочь прочитать скилл и повторить операцию со 100% успехом.

## 4. 🔍 Обязательное глубокое исследование интернета и скилов перед КАЖДЫМ шагом

Перед написанием нового кода или созданием велосипедов каждый агент **ОБЯЗАН**:

1. **Проверить наличие локальных скилов:**
   - Просмотреть директорию `skills/` на предмет готовых инструкций и наработок предыдущих агентов.
2. **Провести глубокий поиск в интернете и GitHub:**
   - Искать готовые проверенные открытые репозитории, спецификации RFC, официальные дампы (RIPE NCC, ARIN, APNIC, CAIDA, BGP looking glasses).
   - Искать существующие agent skills / prompts / scripts для решения аналогичной задачи.
3. **Оценить архитектурное решение:**
   - Выбирать наиболее надежные, быстрые и легковесные решения с открытым исходным кодом.

## 5. 🔐 Управление секретами и конфиденциальными данными

1. **НИКОГДА не коммитить открытые токены доступа в публичный репозиторий!**
   - Публичные репозитории GitHub проверяются Secret Scanning и немедленно отзывают скомпрометированные ключи (`ghp_...`).
2. Все токены, API ключи и учетные данные должны передаваться через **переменные окружения** или файл `.env` (добавлен в `.gitignore`).
3. Для конфигурации используйте `.env.example` как шаблон.

---

## 6. 🚀 Текущий стек и ресурсы репозитория

- **База данных:** SQLite 3 (`isp_cidr.db`) — 508,879 CIDR блоков, 40,650 провайдеров (Украина, США, 49 стран Европы).
- **Язык разработки:** Python 3.10+ (без тяжелых зависимостей, стандартная библиотека `sqlite3`, `ipaddress`, `urllib`, `http.server`).
- **Инструменты:**
  - `isp_tool.py` — утилита запросов, валидации и экспорта (MikroTik, ipset, iptables, nginx, cisco).
  - `web_server.py` — локальный REST API и интерактивный дашборд (порт 8000).
  - `agent_sync.py` — координатор статусов и скилов агентов.
