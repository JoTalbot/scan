## 6. ⚠️ ToS и риски (важно!)

**GitHub Actions** — официальная позиция: запрещены «crypto mining **и server-like задачи**» (AUP). Сканирование портов/поиск уязвимых устройств с раннеров GitHub — **серая зона**:
- Известные кейсы (2026): кампания, запускавшая сканеры cPanel с 583 workflow на 10 репозиториях → **аккаунты забанены**; Operation Muck and Load — 200 репо забанены.
- Лёгкие задачи (обновить CSV раз в 2 недели) — по мнению сообщества GitHub, допустимы; интенсивный скан — риск бана аккаунта и репо.
- **Наш проект уже использует Actions только для генерации REPORT.md — это безопасно.**

**Cloudflare**: AUP запрещает сканирование/атаки — не использовать.
**Vercel**: Hobby только некоммерческий.
**AWS/GCP/Azure free**: сканирование не запрещено явно, но нужна карта, egress-лимиты, и «интернет-скан» может вызвать вопросы поддержки.
**Oracle**: политика «не злоупотребляйте», рекламация неактивных инстансов — держать нагрузку (наш cron это делает).

**Юридически**: сканирование портов само по себе законно в большинстве юрисдикций (прецеденты: US v. Auernheimer отменён; EU — нет запрета), но ToS-нарушение = потеря аккаунтов. Авторизованные цели (свои ASN/лаборатория) — всегда безопаснее.

## 8. Рекомендации для RouterScan (готовый план)

1. **Oracle Always Free ARM** (2 OCPU/12 ГБ): создать 1-2 инстанса, поставить наш репо + SSH-ключ, добавить в `MACHINES` → +2 машины для шардов бесплатно навсегда.
2. **GitHub Codespaces (120 core-ч/мес)**: devcontainer с нашим репо — «арендный» раннер на ~60 ч/мес; запускать через CLI (`gh codespace ssh`).
3. **E2B ($100 кредитов)**: песочницы для аудита SPA (Playwright) — не нагружаем основной сервер.
4. **Shodan InternetDB**: бесплатный CVE-обогатитель для найденных IP — ноль затрат.
5. **GitHub Actions — НЕ использовать для сканов** (риск бана; оставить только отчёты).
6. **OpenHands (self-hosted)** — если захотим давать задачи ИИ-агентам: ставится на Oracle ARM, агенты работают в Docker-песочницах.
